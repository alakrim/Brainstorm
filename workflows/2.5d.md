# 2.5D assets

"2.5D" covers five different techniques. Pick by the look you want:

| Technique | Looks like | Main tools | ~Cost/asset beyond image gen |
|---|---|---|---|
| [A. Lit sprites](#a-lit-sprites-normal-maps-for-2d-lighting) | 2D art that reacts to dynamic lights | Laigter, Depth Anything 3 | $0–0.002 |
| [B. Pre-rendered 3D → sprites](#b-pre-rendered-3d--2d-sprites-dead-cells--isometric-rpg-style) | Consistent 8-direction animated sprites (Dead Cells, classic isometric RPGs) | image→3D, Blender headless | $0.05–1.10 |
| [C. Isometric tiles and props](#c-isometric-tiles-and-props) | Isometric/dimetric worlds | Generator + snapping, or route B | $0–0.40 |
| [D. Parallax layers](#d-parallax-layers) | Depth-scrolling backgrounds | Qwen-Image-Layered, DA3, SAM 3 | $0.03–0.07 |
| [E. 2D skeletal / cutout animation](#e-2d-skeletal--cutout-animation) | Paper-doll animation of one image | Godot Skeleton2D, Unity 2D Animation, Spine | $0 + rigging time |

Also consider **true 3D with a fixed orthographic camera** (3D props + `workflows/3d-props.md`, rendered in-engine with a toon shader). For isometric games with many moving parts it's often cheaper than sprites: one mesh replaces 8 directions × N frames.

*Researched 2026-10-21. Some engine details are marked unverified; test on one asset first.*

## A. Lit sprites (normal maps for 2D lighting)

**Use when:** side-view or top-down 2D with torches, day/night, muzzle flashes.

```
1. Generate sprite: flat even lighting, no baked shadows, plain bg       (00-source-images.md)
2. Cutout: BiRefNet / rembg (isnet-general-use or birefnet-general)
3. Normal map:
   a. Stylized/flat art → Laigter --no-gui batch  OR  scripts/normal_map_from_image.py
   b. Painted/detailed art → Depth Anything 3 (Small/Base) depth → normals via scripts/normal_map_from_image.py --height-map
4. Engine: Godot CanvasTexture | Unity Secondary Texture _NormalMap
```

Tools:

| Tool | License | Notes |
|---|---|---|
| **Laigter** (azagaya/laigter) | GPL-3.0 (the tool; your outputs are yours) | Non-ML; generates normal/specular/occlusion/parallax maps. CLI: `laigter --no-gui -d sprite.png -n` (`-c` specular, `-o` occlusion, `-p` parallax, `-r preset`). Godot plugin exists |
| **Depth Anything 3** Small/Base/Mono/Metric | **Apache-2.0** | Replicate ~$0.001/image. ⚠ Large/Giant weights are CC BY-NC: don't ship them |
| Depth Anything V2 Small | Apache-2.0 | Base/Large/Giant are CC BY-NC |
| Marigold normals | Code Apache-2.0, weights RAIL++-M | Direct normal estimation, good quality; check RAIL use restrictions |
| StableNormal | Apache-2.0 | Direct normal estimation |

Engine setup:

- **Godot 4:** Sprite2D texture → **`CanvasTexture`** with `diffuse_texture`, `normal_texture`, optional `specular_texture` (`specular_shininess` > 1). Add `PointLight2D` / `DirectionalLight2D` and **raise the light's `height`**: at the default near zero, normal mapping is barely visible. Godot expects OpenGL-style normal maps (Y+ up).
- **Unity 6 (URP 2D Renderer):** Sprite Editor → **Secondary Textures** → add the normal map with name **`_NormalMap`**. The material must be **Sprite-Lit-Default**. In the Light 2D component, set **Normal Map Quality** above Disabled.
- If lighting looks inverted vertically, flip the green channel (`scripts/normal_map_from_image.py --flip-y`).

## B. Pre-rendered 3D → 2D sprites (Dead Cells / isometric RPG style)

**Use when:** you need many directions × many animation frames with perfect consistency. Generating each frame as an image drifts; rendering from a 3D model doesn't.

```
1. Character/prop → rigged GLB      workflows/3d-rigged-characters.md (or 3d-props.md for static)
2. Render directions × frames       scripts/blender/render_sprite_directions.py (orthographic, transparent bg)
3. Stylize                          toon/flat material in Blender, outline pass, or post-process
4. Pixel-art (optional)             scripts/pixel_snap.py, or PixelOE / unfake.js, same palette for all frames
5. Pack                             sprite sheet + JSON (the render script can assemble it), or TexturePacker
6. Engine                           Godot SpriteFrames / AnimatedSprite2D; Unity Sprite Atlas + Animator
```

- Camera: **orthographic**. Elevation 30° for a 3/4 view; 30° (2:1 pixel isometric) or 35.264° (true isometric) for isometric. Use exactly the same camera for every asset in the game.
- Directions: 8 for characters (4 for low budgets; mirror E↔W to save memory).
- Costs: the 3D model ($0.30–1.10 per character, rigged) plus rendering (~$0.01 of CPU per character for 8 directions × 8 frames). The rendering is free if run locally or in a CI container.
- Reference implementations: Dead Cells pipeline talk (summarized on 80.lv); `Broxxar/PixelArtPipeline` (Unity, Unlicense); `oddmode-studio/BlenderSpriteSheetImporter` (Godot import plugin).
- Normal maps can be rendered in the same pass (Blender normal pass) and combined with technique A for dynamic lighting on pre-rendered sprites.

## C. Isometric tiles and props

Two routes:

1. **Direct generation (cheapest, for floor tiles and simple props):** use the isometric framing block with the **same reference image** every time, then snap to the exact tile footprint (crop, align to grid; for pixel art use `scripts/pixel_snap.py`, PixelOE or unfake.js). Expect some angle drift. Reject tiles that don't match.
2. **Route B rendered (for anything that must match exactly or animate):** image → 3D → render at the fixed isometric camera.

Hosted option: **PixelLab** (pixel-art generator with REST API and MCP server; isometric tiles, tilesets, 4/8-direction characters; ~$10–50/month, unverified) is worth a test for pixel-art isometric projects.

Engine:
- **Godot 4:** `TileMapLayer` (TileMap is deprecated). Set `tile_shape = Isometric` and `tile_layout` on the **TileSet** resource; enable Y-sort for props.
- **Unity 6:** Grid with **Isometric** (or Isometric Z as Y) cell layout + Tilemap; Transparency Sort Mode custom axis (0, 1, 0) for Y-sorting.

Isometric tile ratio: pixel-art isometric uses 2:1 (e.g. 64×32 tile footprint). Measure the footprint in pixels once and pass it to all snapping steps.

## D. Parallax layers

```
1. Generate the scene: clear foreground / midground / far background, flat lighting
2a. Automatic: Qwen-Image-Layered (Apache-2.0) → 3–8 RGBA layers (recommended 640 px; upscale after)
2b. Controlled: Depth Anything 3 Small → threshold into 3–4 depth bands → refine masks with SAM 3 (text prompts)
3. Inpaint behind removed foreground (Sunburst edit with mask, or Qwen-Image-Edit) so each layer is complete
4. Make each layer tile horizontally (edit call "make left and right edges seamless", or mirror/crossfade)
5. Engine
```

- Cost: ~$0.03–0.07 per scene on a rented H100 for Qwen-Image-Layered (estimate), plus inpainting calls.
- SAM 3 uses Meta's custom SAM License. Read it before shipping, or use depth bands only.
- **Godot 4:** use **`Parallax2D`** nodes (4.3+, replaces ParallaxBackground/ParallaxLayer) with `scroll_scale` per layer and `repeat_size` for tiling.
- **Unity 6:** one SpriteRenderer per layer (sorting layers), scrolled by a small script at a per-layer factor of camera movement. Set `Draw Mode = Tiled` for repetition.

## E. 2D skeletal / cutout animation

**Use when:** a single illustrated character needs idle/breathing/talking or simple motion (mobile, visual novels, card games).

```
1. Generate the character in a neutral pose with separated limbs, flat lighting
2. Split into parts (head, torso, upper/lower arms, ...) with SAM 3 masks or manual cuts
3. Inpaint hidden regions of each part (shoulder under arm, etc.) with an edit call
4. Rig + animate in the engine
```

| Tool | Cost | Notes |
|---|---|---|
| **Godot Skeleton2D + Polygon2D** | Free | Built in; editor UX is rough |
| **Unity 2D Animation package** | Free | Sprite Skin, Skinning Editor with auto-geometry/weights; PSD Importer keeps layers |
| **Spine** | Essential ~$69–99 / Professional ~$379–449 per seat; Enterprise above $500k revenue | Best tooling and runtimes for Godot and Unity |
| Live2D Cubism | Free for individuals/small businesses; PRO above a revenue threshold | Face/bust animation (VTuber-style) |
| Meta Animated Drawings | MIT, **archived Sep 2025** | Reference only |

No reliable AI auto-rigger for 2D characters was found as of Oct 2026. For walk cycles and attacks across many characters, route B is usually cheaper than rigging each in 2D.
